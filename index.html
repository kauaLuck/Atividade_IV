1. Contextualização do Projeto

A DriveEasy é uma empresa de locação de veículos que atende clientes corporativos e individuais. O projeto consiste na implementação de um SGBD Relacional MySQL para solucionar falhas operacionais decorrentes da ausência de um sistema centralizado.

Problemas Eliminados com a Solução Relacional:

  • Overbooking de Veículos: Impedimento de reservas simultâneas para o mesmo veículo no mesmo período através de restrições de chave e validações temporais.
  • Inconsistência na Gestão de Multas: Associação direta e rastreável da infração ao cliente exato que conduzia o veículo no horário do evento.
  • Falha no Histórico de Manutenção: Registro centralizado das intervenções preventivas e corretivas da frota.
  • Redundância de Dados: Aplicação de regras de normalização para eliminação de duplicidades cadastrais.

2. Estrutura do Banco de Dados (`sistema_aluguel_veiculos`)

O esquema relacional é composto por tabelas centrais vinculadas por chaves estrangeiras com regras de integridade referencial ON DELETE RESTRICT e ON UPDATE CASCADE.

Tabela: `categorias`

Campo Tipo Restrições Descrição
id_categoria INT PRIMARY KEY, AUTO_INCREMENT Identificador único da categoria
nome_categoria VARCHAR(100) NOT NULL, UNIQUE Nome da categoria (ex: SUV, Econômico)
descricao VARCHAR(200) NOT NULL Descrição das características
valor_diaria DECIMAL(10,2) NOT NULL, CHECK (valor_diaria > 0) Custo diário de locação

Tabela: `clientes`

Campo Tipo Restrições Descrição
id_cliente INT PRIMARY KEY, AUTO_INCREMENT Identificador único do cliente
nome_cliente VARCHAR(100) NOT NULL Nome completo
cpf CHAR(11) NOT NULL, UNIQUE Cadastro de Pessoa Física
cnh VARCHAR(20) NOT NULL, UNIQUE Carteira Nacional de Habilitação
email VARCHAR(100) NOT NULL, UNIQUE Endereço de e-mail do cliente

Tabela: `veiculos`

Campo Tipo Restrições Descrição
id_veiculo INT PRIMARY KEY, AUTO_INCREMENT Identificador único do veículo
placa VARCHAR(8) NOT NULL, UNIQUE Placa de identificação do veículo
status ENUM 'disponivel', 'locado', 'manutencao', 'inativo' Situação operacional atual
id_categoria INT FOREIGN KEY -> categorias(id_categoria) Vínculo com a categoria do veículo

Tabela: `locacao`

Campo Tipo Restrições Descrição
id_locacao INT PRIMARY KEY, AUTO_INCREMENT Identificador único do contrato
id_cliente INT FOREIGN KEY -> clientes(id_cliente) Cliente responsável pelo contrato
id_veiculo INT FOREIGN KEY -> veiculos(id_veiculo) Veículo locado
data_retirada DATETIME NOT NULL Data e hora da retirada
data_prevista_devolucao DATETIME NOT NULL, CHECK (>= data_retirada) Previsão de devolução do automóvel

3. Aplicação das Formas Normais

1ª Forma Normal (1FN) — Atomicidade

Todos os atributos armazenam valores atômicos. O endereço dos clientes foi desmembrado em colunas individuais (logradouro, numero, bairro, cidade, estado, cep), eliminando campos compostos.

2ª Forma Normal (2FN) — Dependência Total da Chave

Todas as tabelas utilizam Chaves Primárias simples (surrogadas com `AUTO_INCREMENT`). Como não há chaves primárias compostas, garante-se que todos os atributos não-chave dependam integralmente da PK.

3ª Forma Normal (3FN) — Eliminação de Dependências Transitivas

Atributos como valor_diaria e descricao pertencem estritamente à entidade categorias. A tabela de veículos armazena apenas a referência id_categoria, evitando redundâncias caso o valor da diária seja alterado.

4ª Forma Normal (4FN) — Dependências Multivaloradas Independentes

Opcionais do veículo e permissões de circulação regional foram isolados em tabelas associativas próprias para evitar redundância na entidade principal do veículo.

4. Consultas SQL Analíticas (Exemplos)

Abaixo estão destacadas duas das 15 consultas desenvolvidas para apoio à tomada de decisão executiva:

Consulta 1: Faturamento Total por Categoria de Veículo

SELECT 
    cat.nome_categoria,
    COUNT(l.id_locacao) AS total_locacoes,
    SUM(l.valor_total) AS faturamento_total
FROM locacao l
INNER JOIN veiculos v ON l.id_veiculo = v.id_veiculo
INNER JOIN categorias cat ON v.id_categoria = cat.id_categoria
WHERE l.status = 'concluida'
GROUP BY cat.nome_categoria
ORDER BY faturamento_total DESC;

Consulta 2: Listagem de Locações Ativas com Dados do Cliente e Veículo

SELECT 
    l.id_locacao,
    c.nome_cliente,
    v.modelo,
    v.placa,
    l.data_retirada,
    l.data_prevista_devolucao
FROM locacao l
INNER JOIN clientes c ON l.id_cliente = c.id_cliente
INNER JOIN veiculos v ON l.id_veiculo = v.id_veiculo
WHERE l.status = 'ativa'
ORDER BY l.data_retirada DESC;

5. Infraestrutura, Hosting e Backup

  • SGBD Utilizado: MySQL 8.0 / Engine InnoDB (Suporte completo a transações e chaves estrangeiras).
  • Hospedagem na Nuvem: Serviço Cloud MySQL gerenciado via plataforma Aiven.
  • Backup do Banco: Arquivo `.sql` gerado via `mysqldump` contendo a estrutura DDL e as inserções DML.
